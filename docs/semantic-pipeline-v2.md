# Phase 3：离线语义请求与候选回收

`semantic_cleanup/pipeline_v2.py` 接通已校验的 Phase 1 原始快照与 Phase 2 候选契约。它只准备请求文件、接收已有响应并生成审核材料，不提供网络客户端，不调用外部 AI，不写入生产 SQLite 或词典。

## 数据流

```text
原始快照及哈希校验
  → 选择词头、收集同词头全部原始记录
  → requests.jsonl + manifest.json
  → 外部生成阶段（本阶段未执行）
  → 响应 JSONL
  → 请求/快照对应校验 + v2 结构校验
  → review.jsonl（待审核） / rejected.jsonl（错误记录）
```

## 请求准备

在仓库根目录执行：

```sh
python3 -m semantic_cleanup.pipeline_v2 prepare PATH_TO_SNAPSHOT PATH_TO_NEW_REQUEST_DIR --limit 26
```

默认最多选择 26 个词头。优先条件为 Oxford 标记、Collins 至少 3 星、BNC/COCA 排名前 5,000 或已识别考试标签；按源记录顺序选取，**不是把整库按学习价值全局排序后的前 N 词**。`frq` 的语料库含义尚未核实，不作为 COCA 排名使用。

支持 `--words path/to/words.txt` 指定每行一个精确词头；注释行以 `#` 开头。缺少任何指定词头时整次准备报错，不静默遗漏。上限可设为 1–5,000，但本阶段没有运行 5,000 词任务。

选择词头后第二遍读取快照，收集这些词头在源文件中所有位置的记录。非相邻重复词头归入同一个请求；不改变词头大小写，也不把带连字符的前缀与完整单词合并。空的优先词集合会产出数量为零的清单，不扩张选择范围。

请求包含完整 sense JSON Schema、固定提示词版本、原始上下文、本地确定的字段及元数据问题。`custom_id` 是请求内容 SHA-256；源记录、规则、提示词或 schema 改变都会改变 ID。大文件与请求包含原文，仅保存到已有忽略的 `semantic_cleanup/work/` 目录；不要提交至 Git。

两遍选择是流式读取；内存只保存选中词头的记录，但同词头重复数量极大时仍会增长。源快照全文件哈希校验有顺序读取成本。请求包含原始上下文，真实模型处理前还需依据所选供应商增加 token 预算和批次成本控制。

## 模型输出与本地字段

模型只允许返回 `senses`。本地提供词头、音标、词形、考试和词频，组装 provenance；响应夹带其他字段会被拒绝。

- 字符串排名转为数字；未知值与无效值归为 null 并保留警告。零不能被解释为第一名。
- `frq` 与 `coca` 保持独立。
- 中文紧凑考试标记和已知英文标签转成规范名称；未知标签保留在原始上下文并提示审核。
- 只对明确的 `p:`、`d:`、`i:`、`3:`、`s:`、`r:`、`t:` 词形编码提供标签。MDX 扁平时态字符串如“时态: released, releasing”保留在原始记录并提示审核，不推测词形标签。
- 音标只转换 `' → ˈ`、`: → ː` 并拆分变体；不改写元音、不根据前后顺序假定英美地区。所有地区暂记 unspecified。
- 同词头多记录元数据不一致时保留第一条的视图、保留所有原记录，并增加冲突审核原因；不拼出看似确定的新值。

这些字段由本地冻结仅表示响应不能篡改它们，不表示来源数据或解析已经没有错误，审核仍需核查。

## 响应协议

每行必须且只能包含 `custom_id` 和 `output`，后者只能包含 `senses`：

```json
{"custom_id":"请求文件中的完整ID","output":{"senses":[]}}
```

以上仅演示信封格式，空 senses 本身不能通过候选校验。应根据请求中的 `output_schema` 提供完整义项。

```sh
python3 -m semantic_cleanup.pipeline_v2 collect \
  PATH_TO_SNAPSHOT PATH_TO_REQUEST_DIR PATH_TO_RESPONSES_JSONL PATH_TO_NEW_REVIEW_DIR \
  --generator ACTUAL_GENERATOR_NAME --generator-version ACTUAL_GENERATOR_VERSION
```

本地模拟测试应填写明确的模拟名称，例如 `offline-fixture-not-model-call`，不要冒充真实模型调用。响应来源身份由运行者声明，本工具无法自行认证外部供应商。

回收先验证快照和请求文件哈希，再根据真实快照重新计算每个请求，防止锁定字段或上下文被替换。与当前适配器/提示词不一致的旧请求会被拒绝；后续版本需要显式迁移，不能静默混用。

未知 ID、重复响应、非法 JSON、无效候选和伪造字段都记录到 `rejected.jsonl`，后续行继续处理。每个 ID 首次出现后就被占用；同文件后续响应不会覆盖它，修正后应用新响应文件和新输出目录重试。报告区分未收到响应与收到但被拒绝的响应。

`review.jsonl` 保存完整候选、候选内容哈希、审核报告及来源绑定；`manifest.json` 保存计数、缺失 ID 及输入输出哈希。任何成功候选仍是 `needs_review`，可进入生产的数量固定为零。只有完整运行结束才写清单，失败目录不能视为完成结果；已有输出目录拒绝覆盖。

候选 provenance 的 generated_at 是本地组装时间，不是经过供应商认证的生成时间。相同响应重新回收时该时间及候选哈希可能改变；请求 ID 则保持内容确定性。人工审核必须绑定当次候选哈希，不能沿用其他回收版本的批准。

## 验证记录

本地测试共 61 项通过，包括现有 51 项及新增的 10 项链路测试：

- 模拟 release、bank 请求回收，2 个候选进入待审核，0 个获准生产。
- 非相邻重复 release 记录归入同一个请求，元数据冲突进入审核提示。
- 相同快照生成相同请求 ID；修改请求包会被拒绝。
- 非法响应行不会阻断后面的合法行。
- 重复/未知 ID、错误来源引用、模型试图改词频均被拒绝。
- 明确上限、缺词报错、输出目录防覆盖及保守字段转换通过测试。

模拟响应取自 Phase 2 的设计样例并重新绑定本地测试快照，用于验证传递和校验机制，不是模型实际生成结果，也不证明释义质量。此阶段尚未进行真实 AI 语义重构、200 词人工抽检或 macOS 成品重建。

另外，已从 Phase 1 的真实 MDX 小样本为 `00852` 成功生成一条离线请求，保存在 `semantic_cleanup/work/phase3-real-mdx-request-20260912/`。请求文件 SHA-256 为 `c785de78346bb1cf61d356db0c1ed5a0e73c5a84f3c2ebca7970f2e4d1a18279`，来源快照哈希为 `b46ea8c23c52ea933803e5613dbb3b499de15e006969c2d3d32dbaf47102ffa7`。该数字词头仅验证真实数据输入接口，不属于学习核心词筛选结果，也没有送至模型。

下一步真实模型执行需要确定供应商、预算和人工审核安排；当前保留不调用外部 API、不产生费用的约束。可继续开展本地审核工具和预览适配，不依赖外部生成。
