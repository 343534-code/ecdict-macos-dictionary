# 语义重构架构

Phase 1 原始数据层的实现、字段保留规则及验证记录见 [原始数据快照](raw-data-layer.md)。该层先保存可校验的原始记录，后续再显式适配到语义请求结构。

Phase 2 的独立 v2 候选契约、置信度和来源关联规则见 [语义候选数据契约](semantic-schema-v2.md)。下文原有流程描述的是总体目标与旧版 1.0 接口；v2 候选目前只能校验和生成审核报告，不接入旧库或词典导出。

Phase 3 已接通 [v2 离线请求与候选回收](semantic-pipeline-v2.md)：从经校验原始快照准备请求，把已有响应组装为待审核候选。实际模型调用和发布仍未执行。

本项目把 ECDICT 原始数据视为不可变输入。语义重构层不覆盖 MDX，也不直接改写 Apple Dictionary XML；它只产出可验证、可审查、可回退的结构化覆盖数据。

```text
ECDICT 原始数据 / MDX
        │
        ├─► raw-entry JSONL（字段标准化）
        │
        ├─► AI 请求准备（按学习价值分批）
        │       │
        │       └─► 模型输出候选 JSONL
        │                 │
        ├─► 规则校验 + 人工覆盖 + 示例审核
        │                 │
        └─► semantic_entries.sqlite
                  │
                  └─► Apple Dictionary 生成器
                         ├─ 语义词条：现代学习词典结构
                         └─ 未覆盖词条：现有 ECDICT 渲染（安全回退）
```

## 数据职责

| 层 | 位置 | 是否提交到 Git | 用途 |
| --- | --- | --- | --- |
| 原始数据 | 外部 MDX / CSV | 否 | 可复现的来源，不改写 |
| 通用规则 | `semantic_cleanup/word_rules.json` | 是 | 领域标签、排序和长度限制 |
| 人工覆盖 | `semantic_cleanup/sense_mapping.json` | 是 | 高价值词或社区 PR 的审核修正 |
| AI 例句覆盖 | `semantic_cleanup/generated_examples.json` | 是 | 经审核的原创例句 |
| 模型候选与 SQLite | `semantic_cleanup/work/` | 否 | 大批量中间数据，避免仓库膨胀 |
| Apple XML / .dictionary | `dictionary-source/` | 否 | 可再生构建产物 |

## 分批策略

1. **第一批：学习核心词**：Oxford 3000、Collins 星级词及 BNC/COCA 高排名词。
2. **第二批：考试与常用派生词**：含 CET、TOEFL、IELTS、GRE 等标签且有实际学习价值的词。
3. **第三批：长尾词**：仅在模型质量、成本和人工抽检达标后按字母分片处理。

每批都保留来源字段、模型版本、时间和置信度。未通过校验的候选不会进入 SQLite，也不会出现在最终词典中。

## AI 处理规则

- 以英文语义为先：先区分 `release` 的“释放”和“发布”，再合并同一语义下的中文近义词。
- 不以中文逗号列表机械切分或合并；`break` 的“打破、休息、中断、违规”必须保持为不同义项。
- 同一词性内按“常用意义 → 考试常见意义 → 专业意义”排序。
- 中文释义去重，使用 `；` 分隔不同释义，不使用 `、` 作为义项分隔符。
- 英文释义必须是简短原创解释，不复制 Oxford、Cambridge、Collins 或其他受版权保护的原文。
- 默认每个词条最多保留一个原创例句及其中文翻译；低频专业词允许没有例句。
- 模型不能臆造词源、搭配、词频、考试标签或专业标签；不确定时应降低置信度并保留原始覆盖回退。

## 质量门槛

每个结构化词条必须通过：

1. JSON Schema / Python 校验；
2. 词性内连续编号，且每个词性都从 `①` 开始；
3. 最多一个例句，英文和中文翻译成对存在；
4. 中文释义无重复片段、无顿号义项分隔；
5. 英文释义为一句简洁学习者英语；
6. 样本人工审查（高频词、动词、多词性词、专业词、无音标词、长词组）；
7. Apple Dictionary 真实构建与三指查询回归检查。

## 性能与体积

- SQLite 仅在**构建时**读取；最终 `.dictionary` 不依赖数据库，因此不会降低 macOS 查询速度。
- 语义词条只添加一条高价值例句，避免正文无限增大。
- 三指查询首屏固定优先级：词头 / 音标 / 学习价值 → 核心释义 → 词形 → 考试信息 → 词频。
- 未覆盖长尾词保留现有简洁布局，避免因低置信度 AI 输出增加无用内容。

## 全量执行前需要确认的事项

全量处理 340 万词条需要确定模型供应商、预算、每批规模、人工抽检比例和发布策略。当前实现只建立本地、供应商无关的请求与导入接口，不会联网调用模型或产生 API 费用。
